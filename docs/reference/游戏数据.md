## 二、鱼饵（bait_*）

完整定义来自 `bootstrap.html`，原始 JSON：

```json
{"tier":"basic","name":"基础饵","unitPrice":0,"luck":0,"minRarity":0,"maxRarity":1,"fishRarityMultipliers":{},"allowsRelic":false,"allowsGear":false,"allowsChest":false,"isUnlimited":true,"id":"bait_basic"}
{"tier":"low","name":"低级饵","unitPrice":40,"luck":0,"minRarity":0,"maxRarity":4,"fishRarityMultipliers":{},"allowsRelic":true,"allowsGear":false,"allowsChest":true,"isUnlimited":false,"id":"bait_low"}
{"tier":"medium","name":"中级饵","unitPrice":100,"luck":250,"minRarity":0,"maxRarity":8,"fishRarityMultipliers":{},"allowsRelic":true,"allowsGear":true,"allowsChest":true,"isUnlimited":false,"id":"bait_medium"}
{"tier":"high","name":"高级饵","unitPrice":200,"luck":500,"minRarity":0,"maxRarity":8,"fishRarityMultipliers":{"mythic":1.25,"exotic":1.25,"arcane":1.25},"allowsRelic":true,"allowsGear":true,"allowsChest":true,"isUnlimited":false,"id":"bait_high"}
{"tier":"supreme","name":"顶级饵","unitPrice":1000,"luck":1000,"minRarity":1,"maxRarity":8,"fishRarityMultipliers":{"mythic":1.5,"exotic":1.5,"arcane":1.5},"allowsRelic":true,"allowsGear":true,"allowsChest":true,"isUnlimited":false,"id":"bait_supreme"}
```

### 汇总表

| 饵 | 价格 | 运气 luck | 稀有度范围 | 高稀有度倍率 | 遗物 | 装备 | 宝箱 | 无限 |
|---|---|---|---|---|---|---|---|---|
| basic 基础饵 | 0 | 0 | 0~1（普通~罕见） | 无 | ✗ | ✗ | ✗ | ✓ |
| low 低级饵 | 40 | 0 | 0~4（普通~史诗） | 无 | ✓ | ✗ | ✓ | ✗ |
| medium 中级饵 | 100 | 250 | 0~8（普通~奥秘） | 无 | ✓ | ✓ | ✓ | ✗ |
| high 高级饵 | 200 | 500 | 0~8（普通~奥秘） | 神话/奇异/奥秘 ×1.25 | ✓ | ✓ | ✓ | ✗ |
| supreme 顶级饵 | 1000 | 1000 | 1~8（罕见~奥秘） | 神话/奇异/奥秘 ×1.5 | ✓ | ✓ | ✓ | ✗ |

### 字段说明

- **luck**：直接加到「有效运气」的固定值（见下文保底）。
- **minRarity / maxRarity**：能钓到的鱼稀有度区间（闭区间，按 index）。**低于 min / 高于 max 的稀有度完全钓不到（概率 0）**。这是鱼饵最硬性的区别：
  - 低级饵 `maxRarity=4` → 传说及以上永远不出。
  - 顶级饵 `minRarity=1` → 普通鱼永远不出。
- **fishRarityMultipliers**：对指定稀有度的**权重加成**（>1 = 更易出）。中级饵为空，高级/顶级饵才有。
- **allowsRelic / allowsGear / allowsChest**：能否钓到遗物 / 装备 / 宝箱（非鱼掉落）。
- **isUnlimited**：只有基础饵无限，其余有库存。

## 三、保底 / 运气

### 有效运气（脚本 `computeEffectiveLuck`）

```
有效运气 = round( total.luck × (1 + 运气Buff%) ) + 鱼饵luck
运气档位 luckTier = floor( 有效运气 / 1000 )
```

- `total.luck`：`/api/me` 的 `player.stats.total.luck`。
- 运气 Buff：`activeBuffs` 里 `buffType === "luck"` 的 `bonusBasisPoints` 累加（100 = 1%）。
- 鱼饵 luck：静态表（见下）。

### 鱼饵运气静态表（脚本 `BAIT_LUCK`）

```js
const BAIT_LUCK = { bait_basic: 0, bait_low: 0, bait_medium: 250, bait_high: 500, bait_supreme: 1000 };
```

> ⚠️ **脚本当前只覆盖了 luck，没覆盖 `fishRarityMultipliers`**。高级饵的 1.25×、顶级饵的 1.5×（神话/奇异/奥秘）在脚本自算的保底估算里会被忽略，导致高级/顶级饵下的保底估算**偏低**。若要做准，需把倍率也纳入权重估算（近似）。

### 硬保底

- `pity.arcane.currentDryCasts / hardPityCasts`、`pity.exotic.currentDryCasts / hardPityCasts`（来自 `/api/statistics` 的 `pity` 字段）。
- **硬保底具体公式在服务端**，客户端（bundle）里没有那张权重表，脚本只能拿到结果值，无法本地推演「切饵后硬保底变成多少」。

## 四、属性结构（player.stats）

来自 `/api/me` 的 `player.stats`（映射见 `reference/reelax.cn/api/me.html`）：

```json
"stats": {
  "base":            {"strength":339, "intelligence":7193, "luck":0, "endurance":100},
  "rod":             {"strength":0, "intelligence":4950, "luck":4950, "endurance":0},
  "gear":            {"strength":1221, "intelligence":1490, "luck":1511, "endurance":0},
  "medals":          {"strength":39, "intelligence":39, "luck":39, "endurance":39},
  "personalTrophyBonuses": {"personalTournament":39, "weeklyTournament":0, "arcaneSacrifice":0},
  "guild":           {"strength":49, "intelligence":0, "luck":262, "endurance":0},
  "guildTrophies":   {"strength":52, "intelligence":52, "luck":52, "endurance":52},
  "total":           {"strength":1700, "intelligence":13724, "luck":6814, "endurance":191}
}
```

### 总属性公式（逐项相加）

```
total.stat = base + rod + gear + medals + guild + guildTrophies
```

验证（力量）：`339 + 0 + 1221 + 39 + 49 + 52 = 1700` ✓

### 耐力基准

- 耐力有**固定 100 基准**（bundle 里 `D1 = 100`，`Math.max(0, base.endurance - 100)`）。
- 分配点数时写 `endurance: 0` 表示「0 点投入」，结果 `base.endurance = 100`（基准）。
- 可分配总点数 = `base.strength + base.intelligence + base.luck + max(0, base.endurance - 100)`。

## 五、公会图腾（图腾加成）

来自 `/api/fishing/sync` 的 `run.snapshot.effects.guild`（映射见 `reference/reelax.cn/api/fishing/sync.html`）：

```json
"guild": {
  "statBonus":    {"luck":314, "strength":101, "endurance":52, "intelligence":52},
  "totemLevels":  {"luck":4, "members":15, "strength":3, "treasure":3, "experience":3},
  "trophyStatBonus": 52,
  "experienceBonusBasisPoints": 300
}
```

### 图腾加成公式（每级 +1%，floor 取整）

```
guild.stat = floor( totemLevels.stat × 1% × (base + rod + gear + medals + guildTrophies) )
```

验证：
- 力量图腾 Lv3 → 3%：`floor(3% × (339+0+1221+39+52)) = floor(49.53) = 49` ✓
- 运气图腾 Lv4 → 4%：`floor(4% × (0+4950+1511+39+52)) = floor(262.08) = 262` ✓

> 注意：`statBonus`（如 strength:101）是**公会层级的展示值**，不直接加到玩家 `stats.guild` 上；玩家实际拿到的 `guild.stat` 只由「图腾等级 × 1%」决定。
> `trophyStatBonus`（52）对应玩家的 `guildTrophies`（固定加成，flat 里已包含）。

### 赛后加点力量反解（脚本 `applyPostRespec` 用它）

```
设 flat = rod + gear + medals + guildTrophies（固定加成，不随分配变）
   totemPct = totemLevels.strength / 100
目标总力量 target，求基础力量 base：
   base ≈ target / (1 + totemPct) - flat
   （再微调 ±3 消除 floor 的 ±1 误差；目标落在 floor 空档时最近值差 1，数学上不可达）
```

## 六、每日盈亏数据

### 数据源（脚本 `state.playerGold / playerRelics / playerFragments`）

| 字段 | `/api/me` | `/api/fishing/sync`/`state` |
|---|---|---|
| 金币 | `player.gold` | `playerPatch.gold` |
| 遗物 | `player.relics` | `playerPatch.relics` |
| 碎片 | `player.fragments` | `playerPatch.fragments` |

脚本拦截器被动采集这三项（零额外请求）。

### 每日盈亏计算

- 基准快照：每天凌晨 0 点记录 `{ date, gold, relic, fragment }`（当时的当前值）。
- 实时盈亏：`当前值 − 基准值`；金币正=赚、负=亏，遗物/碎片同理。
- 跨天结算：检测到日期变化时，把「昨天最终值 − 昨天基准」写入历史，再记录今天新基准（凌晨 0 点重置）。
- 历史聚合：日=每天一条；周=按自然周（周一~周日，取周一日期为 key）；月=按自然月（`YYYY-MM`）。

> 限制：脚本关闭期间不运行，跨天结算依赖脚本运行时检测；若跨天时脚本未运行，下次打开会用「当前值 − 旧基准」近似昨日盈亏，边界处有少量误差。

### 存储

- 基准快照：localStorage key `arcane_daily_balance_snapshot`
- 历史记录：localStorage key `arcane_daily_balance_history`，每条 `{ date, gold, relic, fragment }`
