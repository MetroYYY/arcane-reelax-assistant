## 签名机制

游戏接口分两类：

- **免签接口**：`/api/me`（响应头下发 `x-arcane-request-proof`）
- **需签名接口**：其余所有，HMAC-SHA256 签名

签名格式：

```
待签明文 = "v1\n" + METHOD + "\n" + path + "\n" + 毫秒时间戳 + "\n" + body
签名     = base64url( HMAC-SHA256( key=proof, msg=明文 ) )
请求头    = x-arcane-request-proof + x-arcane-request-timestamp + x-arcane-request-signature
```

其中 `path` 为 `pathname + search`，`METHOD` 为大写。**时间戳必须是服务器时间**：`服务器时间 = 本地时间 + 偏移`，偏移由响应头的 `x-arcane-server-time` 校准（`偏移 = x-arcane-server-time - Date.now()`，游戏任何接口响应都会带这个头，持续校准）。签名时间戳用本地时间会导致「请求签名已失效」。

403 → 重新从 `/api/me` 拿 proof 后重试一次。

## 三、采集服务（脚本 → 自建服务器）

> 非游戏 API，走 `originalFetch` 直连自建服务器，**无需 HMAC 签名，不占游戏请求预算**。

服务地址：`https://reelax.hsiyue.com`（Go 实现，代码见 `server/main.go`，systemd 服务见 `server/reelax-collector.service`）

| 接口 | 方法 | 触发条件 | 用途 | 去重/限制 |
|------|------|---------|------|----------|
| `/survey` | POST | 玩家提交当前问卷 | 问卷编号与答案 | 按 uid 和问卷编号去重 |
| `/usage` | POST | 脚本初始化 | 使用人数/版本统计 | 按 uid 去重 |
| `/report` | POST | 玩家提交 bug 反馈 | bug（带日志+面板设置） | 10 分钟冷却 |
| `/feedback` | POST | 玩家提交意见建议 | 建议（纯文本） | 10 分钟冷却 |
| `/version` | GET | 脚本初始化 | 版本检查 | 无 |

## 四、保底相关数据源（近期讨论，待实现）

保底进度来自 `/api/statistics` 的 `pity` 字段：

```
pity.effectiveLuck   → 有效运气 = total.luck × (1 + 运气Buff) + 鱼饵 luck
pity.luckTier        → 运气档位 = floor(effectiveLuck / 1000)
pity.baitId          → 当前鱼饵
pity.weatherId       → 当前天气
pity.arcane.currentDryCasts / hardPityCasts   → 奥秘连续未出 / 硬保底
pity.exotic.currentDryCasts / hardPityCasts   → 奇异连续未出 / 硬保底
pity.*.maxDryCasts   → 历史最大连续未出（参考，不参与进度计算）
```

其中 `effectiveLuck` 的三个组成部分，脚本均有常驻数据源可自算：

- `total.luck` ← `/api/me` 的 `player.stats.total.luck`
- 运气 Buff ← `activeBuffs` 里 `buffType==="luck"` 的 `bonusBasisPoints` 累加
- 鱼饵 luck ← 静态表（基础0/低级0/中级250/高级500/顶级1000）

只有 `currentDryCasts` 和 `hardPityCasts` 需要 `/api/statistics` 主动请求（或本地追踪 + 低频校准）。
